Notebooks from ML course

Репозиторий содержит ноутбуки из курса по машинному обучению в финансах (ML for Finance, https://otus.ru/lessons/ml-finance/).

## Быстрый старт

```bash
pip install -r requirements.txt   # версии совпадают с теми, на которых сняты выводы ноутбуков
python -m pytest test_mlfin_core.py -q    # 70 passed
```

`HW6`–`HW8` выполняются за 8–18 минут каждый и трогают финальное тестовое окно ровно один раз.
Ноутбуки закоммичены **с сохранённым выводом исполненного кода**, поэтому результаты видны в
GitHub без запуска. Данные тянутся из `yfinance`; локальный CSV имеет приоритет, синтетические
данные используются только как явно обозначенный запасной вариант.

Для воспроизводимости прогонов из командной строки (ноутбуки выполняются через `nbclient`):

```bash
python -m nbconvert --to notebook --execute --inplace HW7_Validation_Leakage_Uncertainty.ipynb
```

## Описание ноутбуков
### HW4_DataFromFile.ipynb
Этот код реализует комплексную систему для анализа и бэктестинга торговых стратегий на финансовых рынках, поддерживая акции (например, GBTC, BITF) и криптовалюты (например, BTC, ETH).
**Ключевые функции:**
1. **Загрузка данных**: Загружает исторические данные о ценах из локальных CSV-файлов (например, GBTC.csv, BTC.csv).
2. **Предобработка данных**: Очистка данных, удаление дубликатов и выбросов (IQR), нормализация для ML.
3. **Генерация признаков**: Создание технических индикаторов (EMA, RSI, MACD) и лагированных признаков. Целевая переменная: 1 (рост) или -1 (падение).
4. **Торговая стратегия**: Реализация технической стратегии (покупка: цена > EMA20, RSI < 65, MACD > Signal; продажа: цена < EMA20, RSI > 35, MACD < Signal) с оптимизацией параметров.
5. **Машинное обучение**: Обучение моделей (градиентный бустинг, случайный лес, логистическая регрессия) с оптимизацией гиперпараметров (GridSearchCV).
6. **Бэктестинг**: Оценка стратегий на обучающей и валидационной выборках с учетом транзакционных издержек.
7. **Визуализация**: Интерактивный дашборд (Plotly, ipywidgets) для анализа результатов.
   
### HW4_MV.ipynb
Построение моделей классического машинного обучения (ML) для формирования торговых стратегий на ежедневных данных (Yahoo Finance, 2020-01-01).
**Основные этапы:**
1. **Обработка данных**: Очистка, заполнение пропусков, устранение дубликатов, нормализация (Z-Score) и сохранение в CSV.
2. **Моделирование**: Дополнение стратегии Strategy1 (EMA+RSI+MACD) тремя моделями ML (Gradient Boosting, Random Forest, Logistic Regression). Использование продвинутых алгоритмов и оптимизация параметров.
3. **Бэктестинг ML стратегий**: Разделение данных на train/valid. Оценка стратегий с регуляризацией (Lasso, Ridge, Elastic Net) и оптимизацией параметров деревьев решений. Расчет метрик: Precision, Recall, Accuracy, F1-Score, ROC AUC.
4. **Сравнение**: Бэктестирование стратегий без ML и сравнение результатов в сводном дашборде.

## HW6–HW8: пересмотренная часть репозитория

`HW6`–`HW8` — это не «ещё три домашки», а переработка всего, что было выше. Они построены вокруг
одного вопроса, которого не было в `HW1`–`HW5`: **что в этом репозитории реально выдерживает
проверку, а что нет.** Все три ноутбука используют реальные данные (SPY, `yfinance`), один
идентичный протокол и общие библиотеки в `mlfin_core.py`.

Общая дисциплина, которую вводят эти три ноутбука:

1. **Любая метрика сравнивается с нулевым бенчмарком.** Accuracy — с accuracy всегда-«в лонг».
   Sharpe — с buy-and-hold. Интервал — с заявленным уровнем покрытия. Модель, которая не прошла
   базу, нигде не отмечена как победившая.
2. **Ничего не выбирается на финальном тестовом окне.** Последние 20% баров касаются один раз.
3. **Неопределённость сообщается, а не подразумевается.** Точечная оценка Sharpe на нескольких
   сотнях баров — это утверждение о шуме, поэтому у каждой ключевой цифры есть интервал.

### HW6_StatisticalBaselines_ARIMA_ETS.ipynb

Противоположный конец шкалы сложности: ARIMA, ETS, структурная модель, константа и случайное
блуждание — всё на одном протоколе, с HAC-корректированным тестом Diebold–Mariano и
калибровкой интервалов.

Ключевой результат — **отрицательный, и в этом его ценность**:

| Метрика (OOS, 504 бара) | Значение |
|---|---|
| Лучшая модель vs константа (RMSE) | +0.01% — то есть ничто |
| Моделей (fitted), значимо лучше константы | **0 / 6** |
| Моделей (fitted), значимо лучше случайного блуждания | 6 / 6 |
| Константа бьёт случайное блуждание | **5 / 5** исторических окон |
| Подразумеваемый AR(1) rho окна | −0.087 (для победы над константой нужен rho > 0.5) |
| Покрытие интервалов (номинал 0.95) | 0.970 / 0.966 / 0.972 |

Вывод, который стоит процитировать: «модели бьют случайное блуждание» — это свойство слабости
случайного блуждания на дневных доходностях, а не свойство ARMA-структуры. Все модели
tie константу. Ранний черновик этого же ноутбука показывал «успех» над случайным блужданием —
и ошибался: нулевые бенчмарки пересчитывались раз в 21 бар, то есть «завтра равно сегодня»
превратилось в «завтра равно цене трёхнедельной давности». Это и есть главный урок ноутбука:
**выигрыш относительно бенчмарка, реализованного неправильно, — это не выигрыш.**

По волатильности вывод противоположный и столь же честный: на 5-барной реализованной
волатильности побеждает именно персистентность (0.333 против 0.560 у константы и 0.684 у лучшей
fitted-модели), ни одна модель её значимо не превосходит, и персистентность выигрывает в 5 из 5
окон. Прогнозируемость зависит от того, что прогнозируется.

### HW7_Validation_Leakage_Uncertainty.ipynb

Пять экспериментов, в каждом из которых меняется **только дисциплина валидации**, а модель и данные
остаются прежними.

| Эксперимент | Что изменилось | Результат прогона |
|---|---|---|
| 1. Правило разбиения | random K-fold / purged K-fold / walk-forward | три схемы выбрали три разные модели; разброс OOS accuracy 0.0033 при разбросе CV 0.0229 |
| 2. Утечка в препроцессинге | скейлер на train+test | искажение CV ≤ +0.0020 — на этих признаках несущественно |
| 3. Заглядывание в будущее | один признак с форвардной доходностью | accuracy 0.4832 → 0.9566 (+0.473) |
| 4. Шум отбора | 24 конфигурации градиентного бустинга | ни одна не обошла climatology ни в CV, ни вне его; ранг CV против ранга OOS: ρ = +0.338 |
| 5. Зависимость от дат | 15 путей CPCV | Sharpe путей p05 −0.504 / среднее −0.196 / p95 0.024; 86.7% путей ≤ 0 |

Автоматический детектор утечки находит признак с форвардной доходностью сам, по данным: его
корреляция с целью в 18.1 раза выше медианной по набору признаков. Важная деталь: абсолютный
порог 0.95 этот случай **пропустил бы** — из-за deadband ни один признак не может быть идеальной
переформулировкой трёхклассовой метки, поэтому детектор работает относительно медианы.

Честный итог симуляции: на OOS-сегменте CAGR −9.70% и Sharpe −0.560 против buy-and-hold
+17.67% и 1.106; 95% bootstrap-интервал Sharpe [−0.634, 0.520], PSR 0.412, DSR 0.018 —
**убедительного преимущества нет**.

### HW8_Boosting_MLflow_Leaderboard.ipynb

Соревнование LightGBM / XGBoost / CatBoost / scikit-learn HGB / логистической регрессии на
идентичном протоколе, с логированием в MLflow и лидербордом, **восстановленным из хранилища**, а не
из переменных в памяти.

| | Значение |
|---|---|
| climatology accuracy | 0.5073 |
| Модели, обошедшие climatology по accuracy | **0 / 5** |
| Лучший OOS Sharpe модели vs buy-and-hold | 0.620 против **1.106** |
| Модели, обошедшие buy-and-hold по Sharpe | **0 / 5** |
| Лучшая по accuracy ≠ лучшая по Sharpe | да (LogisticRegression против CatBoost) |
| ECE / Brier skill score | 0.231 / −0.0077 → как инструмент sizing непригодна |
| Permutation importance (только на OOS) | top-1 `close_loc`, топ-3 = 48.3% эффекта, 6/23 признака без эффекта |
| MLflow | 7 прогонов, SQLite; таблица в памяти совпала с восстановленной из хранилища |
| 95% CI / PSR / DSR (5 попыток) | [−0.485, 0.673] / 0.591 / 0.204 → **убедительного преимущества нет** |
| MinTRL для Sharpe 1.0 | 183 года |

Расхождение рейтингов по accuracy и по Sharpe — само по себе результат: модели учат базовую долю
растущего индекса, а не направление. Это истинное и бесполезное утверждение.

### mlfin_core.py и test_mlfin_core.py

Общая библиотека, на которой построены `HW6`–`HW8`, и набор тестов на её инварианты:

- причинные признаки и метки с явным контрактом времени решения;
- `FoldSafePreprocessor` — и, намеренно, его антипаттерн `fit_on_full_sample`, чтобы вред от
  него можно было **измерить**, а не утверждать;
- purged K-fold с эмбарго, walk-forward, комбинаторная purged CV;
- блочный бутстрэп, PSR, DSR, MinTRL;
- conformal-интервалы, reliability, ECE, Brier skill score;
- издержки внутри потока доходностей и метрики с защитой от вырожденных случаев.

`python -m pytest test_mlfin_core.py -q` → **70 passed**.

### Как читать отрицательные результаты

Три ноутбука подряд не нашли прибыльной стратегии, и это не неудача, а содержание работы.
Каждая цифра выше получена исполненным кодом в этом репозитории и сопровождается
бенчмарком и интервалом неопределённости. Заявления из `HW5_MV.ipynb` (`Accuracy = 0/1`,
`total_return = 10000%`) некорректны и в этот раздел сознательно не перенесены.
